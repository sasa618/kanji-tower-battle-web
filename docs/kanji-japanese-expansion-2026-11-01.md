## 判定の方法

候補は前回調査の421字（参考案218字はすべてこの中に含まれる）とした．全字について漢字辞典オンラインの親字の項目を取得し，日本語の音訓・意味，常用・人名用の別，JIS水準，日本の漢和辞典（大漢和辞典・日本語漢字辞典・新大字典・大字源・大漢語林）の検字番号，日本の名字・地名の用例を確認した．初回の取得では69字が一時的に「項目なし」となったが，再取得ですべて項目を確認できたため，項目なしを理由に保留した字はない．

採用の条件は次のとおりである．Unihanの読みや規格への収録だけでは採用していない．

1. 漢字辞典オンラインの親字の項目に，日本語の音読みまたは訓読みと，日本語の意味がある．
2. 常用漢字・人名用漢字・JIS第1～第4水準のいずれかである．JIS外の字は，仕様書が確認済みとした咅・諰と，国字または日本の名字・地名の用例がある字に限る（日本の漢和辞典の検字番号だけでは，中国の古典にだけ現れる字と区別できないため）．
3. 意味の説明が，現代中国語の口語・音訳・中国の固有名詞（川・山・民族の名）だけではない．日本の名字・地名の用例があれば固有名詞の字でも採用した（渭・湘）．
4. 基本20字から，既存の式と採用した字の式だけで作れる．元フォントに字形があり，当たり判定を生成できる．

新規候補どうしで材料の組が重なるときは，仕様書4.2の順に，後続の字（特に常用漢字）が多い字，常用・人名用・JIS水準の高い字，材料との対応が説明しやすい字の順で選んだ．仕様書4.3・4.4で指定された式は，その組を優先して割り当てた．

## 実装と検証

`src/data/kanji.json` と `src/data/recipes.json` の末尾に追加し，`tools/build-font.py` で配信用フォント，`npm run glyphs` で字形・当たり判定，`tools/build-discovery-cards.ts` で合体で作れる304字の共有画像を生成した．フォントの輪郭は全322字が元のBoldと一致し，既存107字の当たり判定データは変わっていない．最大画数は20画（譟・譩）になり，ランキングの上限は漢字データから算出されるため20画を受け付ける．画数別の配色は最小～最大画数の範囲で決まるため，既存の字の色も少し変わる．再訪した端末に新しいフォントを配るため，フォントURLの版を更新した．

自動テスト93件，型検査，公開URL付きビルド，全306レシピの上下2通り（612通り）の接触合体の検証に成功した．テストには，既存107字・89レシピの不変（ハッシュ），喿→燥・圭→佳・亘→恒・咅→培・从→坐・吴→誤の連鎖，倍・保・淋・体の別経路，1回の落下あたりの得点が上限8画を超えないことを加えた．ブラウザー（Chrome）の390×844とPC幅で，全字発見状態の図鑑の表示・選択とはみ出しがないこと，スマホ幅での落下操作で新しい合体（諰・灶・劯・佃・炅・沁）が図鑑に記録されることを確認した．iPhone Safari・Android Chromeの実機，X上のカード表示は確認していない．

当たり判定データ（glyphs）の配信量はgzipで約129KBから約475KBに増えた．最も複雑な新字（嬲・焱・𣷹・譟）だけを30個積んだ試験では，PCでの物理処理のp95は14.2msで，既存の複雑な字（森・詩・想・晶）の7.0msの約2倍だった．スマホでの描画込みの性能は未検証である．
