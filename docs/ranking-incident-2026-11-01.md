# ランキングの読み取り上限超過と索引追加（2026-11-01）

本番D1が無料枠の日次読み取り上限超過（7500）を返し，ランキング3種目・health・statsが503になっていることを確認した．直近24時間の管理情報は読み取り14,333,707行で，Insightsでは `DELETE FROM sessions WHERE created<?` が2,010回・13,443,684行を占めていた．

`0004_retention_indexes.sql` を本番D1に適用し，`sessions(created)` と `scores(created)` の索引を追加した．通常の移行コマンドは上限超過で履歴を読めなかったため，SQLファイルのインポートで適用した．両方の索引がsqlite_masterに存在する場合にだけ移行履歴を追加するSQLも実行し，追加成功を確認した．Workerやゲームの再配布は不要である．保存期間・削除頻度は変更していない．

ローカルでは索引を使用した範囲検索になることと，期限内の行が残ることを確認した．関連するAPIのテストを含む15件が成功した．本番で実際に削減された読み取り量は，日次上限のリセット後に確認する必要がある．

2026-11-01 22:18（日本時間）時点の本番スコアは104件．通常の件数取得も上限超過だったため，scoresだけをエクスポートして手元で件数を数え，エクスポートファイルは削除した．これは登録記録の件数であり，利用者数やプレイ回数ではない．

無料枠は毎日00:00 UTC（日本時間09:00）にリセットされる．索引追加で当日消費済みの枠が戻るわけではない．
## 続く改善と公開（2026-11-01）

ランキングの一覧をWorkerインスタンス内で種目ごとに60秒共有し，同時要求も同じ問い合わせを待つようにした．Cache APIの有無や失敗に依存せず動き，DBがエラーを返す間も15秒の間隔を置いて過剰な再試行を防ぐ．別インスタンスや再起動後には再取得するため，全世界で1分に1回だけの取得を保証するものではない．

期限切れのセッションとスコアの整理を各要求から外し，毎時0分のscheduledイベントへ移した．保存期間はセッション2日，スコア90日のままとした．今回の障害で消費済みの日次枠は戻らず，成功時の本番読み取り量の確認はリセット後に必要である．

同じプレイ・同じ記録の再送は，登録済みの1件に対する順位を返す．別内容での上書きは拒否する．送信に成功した名前を端末に保存し，再送ボタン・結果から一覧への移動・直近送信時の種目別順位を表示する．端末のキャッシュは1分，明示的な更新は最短5秒間隔とした．

自動テスト90件・型検査・公開URL付きビルドが成功．100件の同時取得がDB問い合わせ1回になること，応答喪失後の再送が1件のままであること，定期整理で期限内のデータが残ることを確認した．390×844のブラウザーで試験用API応答を使ってランキングの表示・種目切替を確認し，横にはみ出しやページ内エラーがないことを確認した．試験用スコアは本番に追加していない．
