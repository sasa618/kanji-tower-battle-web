# ボーナスはてなとレア・レジェンド漢字（2026年11月2日）

公開版（基本20字・全318字・302レシピ）に，虹色のブロック「ボーナスはてな」と，レア漢字・レジェンド漢字の区分を加えた．最終は基本20字・全377字とボーナスはてな・361レシピである．この作業はAI（Claude）が担当し，仕様は本人との相談で決めた．本番への反映は本人の指示があるまで行わない．

## ボーナスはてな

- 候補の3枠のうち1枠に出る，画数0の正方形のブロックである．文字は `？` を使い，`kanji.json` では `wild` を立てる．輪郭はフォントではなく，`tools/build-glyphs.mjs` が80px四方のうち72pxの正方形を生成する．
- 見た目は明るい虹色のグラデーションに濃紺（台と同じ色）の枠，白い「？」である．動かさない．
- 塔に相手の字がないときは出ない．開始直後と前回の出現から2手は出ず，3手目から出る確率が3％になり，1手ごとに2％ずつ上がって30％で止まる（`WILD_CHANCE`）．2手続けては出ない．
- 相手のない字に当たったときは何も起きず，0画のブロックとして乗る．台から落ちれば他の字と同じく終了の条件になる．
- 遊び方には，どの字になるかを書かず，結果を「？」で隠した図で説明する．

## レア・レジェンドの決め方

1. 基本の字にボーナスはてなを当てた結果はレアである．
2. 合体でできた字に当てた結果は，画数の大きさや字の格でレアかレジェンドに分けた．
3. レア・レジェンドの字に何かを足した結果は，はてなの2回目も通常の合体も，全部レジェンドである．
4. 既存の字では，3回の合体で届く常用の13字（待・億・憶・臆・恩・憧・瞳・咽・姻・栓・詮・垣・恒）をレア，4回の添・燥をレジェンドにした．墨は濹の材料であるため入れていない．これらの区分は `src/data/index.ts` で付け，`kanji.json` の公開済みの項目は変えていない．

結果の字は，元の字を部品として本当に含むものに限った（例：鬱は林を含むので林から作る）．画数は Unihan の `kTotalStrokes` を基準に，日本の字体で数が異なるもの（器15・瞬18・臨18・萌11・黛16・頬16・謎17）は日本の数え方を採った．謎は16画とする辞書もある．黯は21画とした．

## 画面と共有

- 合体の予告の光は，結果が通常なら黄（従来どおり），レアなら氷色の銀（白い線に青のにじみ），レジェンドなら虹の線にする．
- レア・レジェンドの字は，盤面・候補欄・図鑑・結果画面・共有画像のすべてで，濃い縁を付けた銀・金のグラデーションで描く．画数で決まる色の帯からは外れる．
- 図鑑は通常・レア・レジェンドの3区画に分け，レアは銀の枠と RARE の印，レジェンドは金の枠と LEGEND の印を付ける．番号は区画ごとに R01・L01 のように振る．進捗は区画ごとに数える．ボーナスはてなは図鑑に載せない．
- 図鑑からのX共有では，投稿文の字の前に【レア漢字】【レジェンド漢字】を付け，カード画像に銀か金の帯を描く．カード画像は新しい59字と，区分の付いた既存の15字について作り直した．他の300字の画像は変えていない．
- ランキングの検証は，0画のブロックが乗ったまま終わると総画数が字数を下回ること，1手で20画以上増えることがあることに合わせ，`score<count` の条件を外し，1手あたりの上限を8画から12画にした．最大画数は龖の32である．

## 記録への影響

ボーナスはてなは0画のブロックを大きな画数の字に変えるため，導入後の総画数は導入前より伸びやすい．90日のランキングは導入後の記録に入れ替わっていく．これは本人が了承した．

## 確認

`npm run check` と `npm test`（118件）が通ることを確認した．データの検査として，はてなの結果が全部レアかレジェンドであること，レア・レジェンドを材料にした結果が全部レジェンドであること，同じ字に2つのはてなの結果がないこと，候補の抽選でブロックが2手続けて出ないことをテストに加えた．

## テストプレイ後の修正（同日）

本人のローカルでのテストプレイを受けて，次を直した．

- 銀・金の字で一画ごとの境界線が見えていた．フォントの輪郭は画ごとに重なっているため，縁を後から描くと重なりの線が出る．縁を先に描き，その上からグラデーションで塗る順に変え，外側の輪郭だけが残るようにした（`drawGlyph`）．カード画像はレア・レジェンドの74字を作り直した．
- 結果画面と記録画面のX共有は「Xでシェア」の1つだけにした．押した時点でウィンドウを開き，共有画像の用意ができ次第そのウィンドウを投稿画面に進める．用意ができた後は同じ位置の操作が直接のリンクになるので，ポップアップが止められても次の操作で開く．図鑑の共有も同様に，下のリンクを出さない．状況の文は「投稿画面が開かない場合は、もう一度「Xでシェア」を押してください。」だけにし，塔の画像が含まれない旨は出さない．投稿文のゲームURLは `VITE_PUBLIC_URL` から入る（公開ワークフローでは常に設定される）．
- Worker に届かないときのランキングは，端末がオンラインである限り「全国ランキングはアクセス数の制限により一時停止中です。」と出す（Cloudflare の日次上限の 429 は CORS ヘッダーが無く，ブラウザでは通信失敗として見えるため，この判定にした）．この表示は Worker から次の応答があるまで続く．結果画面の接続失敗の文も同じにした．

確認は，ローカルの Worker（`npm run dev:api`，ローカル D1）に `.env.development.local` で接続し，Playwright で，ゲーム終了→名前の送信→「Xでシェア」でウィンドウが投稿画面（共有リンク付き）に進むこと，操作が1つであること，Worker への要求を止めた状態で記録画面と結果画面に一時停止の文が出ることを確かめた．本番の Worker は 11月2日 9時（JST）の時点で3種目とも 200 を返していた．

候補欄のボーナスはてなは，画数の欄に太字（TowerDisplay）で「ボーナス」と出し，枠を黄と青で光らせる（動きを減らす設定では光を止める）．本人の指示で，同日に Worker（版 `8a542cc6`）と Pages へ反映した．反映の前に，ローカルの Worker で2回のプレイ・送信・共有・ランキングの表示を通して要求を数え，プリフライト（OPTIONS）が0件であること，1プレイあたり `/sessions` と `/events` の2件だけであること，ランキングの一覧は種目ごとに1分の間は再取得しないことを確かめた．
